## 3. 接口验证（curl）

以下均为实际执行结果。

### 3.1 注册

| 场景 | 期望 | 实际 |
|---|---|---|
| 正常注册 | 200 + 用户信息，**响应不含 `password_hash`** | ✅ 200，body 仅含 id/username/email/created_at/updated_at |
| 用户名重复 | 409 | ✅ 409 `"用户名/邮箱已被注册"` |
| 邮箱重复 | 409 | ✅ 409 同上 |
| 必填字段为空 | 400 | ✅ 400 `"用户名/密码/邮箱不能为空"` |

补充：直接查询数据库确认 `password_hash` 为 bcrypt 散列（长度 60，形如 `$2a$10$...`），非明文。

### 3.2 登录（统一 401 防枚举）

| 场景 | 期望 | 实际 |
|---|---|---|
| 用户名密码正确 | 200 + `Set-Cookie: token=...; HttpOnly; SameSite=Lax; Max-Age=86400` | ✅ |
| 密码错误 | 401 `"用户名或密码错误"` | ✅ |
| 用户不存在 | 401 `"用户名或密码错误"`（**与密码错误完全一致**） | ✅ 状态码与响应体均一致 |
| 响应体不含 Token | 不出现 | ✅ Token 字段为 `json:"-"`，仅用于写 Cookie |

补充：登录成功后查询 `tokens` 表，确认写入记录且 `user_id` 为登录用户的 id。

### 3.3 鉴权中间件

| 场景 | 期望 | 实际 |
|---|---|---|
| 不带 Cookie 访问 `GET /user/me` | 401 | ✅ `"登录已失效，请重新登录"` |
| 携带有效 Cookie 访问 | 200 + 本人信息 | ✅ |
| 伪造 Token | 401 | ✅ |
| 公开接口（注册/登录）不受拦截 | 200 | ✅ 注册仍可用 |

### 3.4 退出登录（服务端失效）

| 步骤 | 期望 | 实际 |
|---|---|---|
| 登录并保存 Cookie | 200 | ✅ |
| 退出登录 | 200 + `Set-Cookie: token=; Max-Age=0` | ✅ |
| 用**退出前的旧 Token** 再访问 | 401 | ✅ |
| 查询数据库 `tokens` 中该 Token | 记录已删除（0 行） | ✅ `SELECT COUNT(*)` = 0 |

> 这一组证明：退出是**服务端凭据销毁**，不只是清理浏览器 Cookie。

### 3.5 个人信息

| 场景 | 期望 | 实际 |
|---|---|---|
| 查看个人信息 | 200 + 本人信息 | ✅ |
| 修改邮箱 | 200 + **新邮箱 + 新 updated_at** | ✅ 响应与数据库均为新值 |
| 改为自己当前邮箱 | 200（幂等） | ✅ 未误报 409 |
| 改为他人已占用邮箱 | 409 `"邮箱已被注册"` | ✅ |

### 3.6 修改密码

| 场景 | 期望 | 实际 |
|---|---|---|
| 原密码错误 | 400 `"原密码错误"` | ✅ |
| 正常修改 | 200 | ✅ 数据库散列已更新 |
| 用新密码登录 | 200 | ✅ |
| 用旧密码登录 | 401 | ✅ |

### 3.7 待办与数据隔离

两个用户分别登录后操作：

| 场景 | 期望 | 实际 |
|---|---|---|
| alice 创建待办 | 200 | ✅ id=5 |
| bob 创建待办 | 200 | ✅ id=6 |
| bob 查询列表 | 只包含自己的 | ✅ 仅 id=6 |
| bob 访问不属于自己的待办（详情） | 404 | ✅ `"备忘录不存在"` |
| bob 修改不属于自己的待办 | 404 | ✅ |
| bob 删除不属于自己的待办 | 404 | ✅ |
| 未登录访问 `/todos` | 401 | ✅ |

**对照实验**（排除"记录不存在"造成假通过）：修复缺陷后再次用真实 MySQL 验证，三个方向同时确认：

| 操作 | 实际 |
|---|---|
| alice 访问**自己的**待办详情 | ✅ **200** + 正确的 titles/content（证明功能正常） |
| bob 访问 alice 的同一条 | ✅ 404（证明拒绝生效） |
| bob 删除 alice 的同一条 | ✅ 404，且 alice 数据未被删除 |
| alice 删除自己的 | ✅ 200 |
| 删除后再查 | ✅ 404 |

数据库侧确认：`todos` 表存在 `user_id` 列且写入正确（alice 的记录 `user_id=1`，bob 为 `2`）；加列前遗留的旧数据 `user_id=0` 已清理。

## 5. Docker 验证记录

### 5.1 镜像构建

```powershell
# 宿主机交叉编译 Linux 二进制
$env:CGO_ENABLED="0"; $env:GOOS="linux"; $env:GOARCH="amd64"
go build -trimpath -ldflags="-s -w" -o build/app-linux todo.go

docker build -t todo-app:v1 .
docker images todo-app
```

结果：

| 项目 | 值 |
|---|---|
| 二进制大小 | 19,726,498 字节（约 19.7 MB） |
| 应用镜像 | `todo-app:v1` — **43 MB** |
| 基础镜像 | `alpine:3.20` — 12.2 MB |

> 镜像仅含运行所需内容（二进制、`web/`、容器配置、CA 证书、时区数据），**不含编译工具链，也不含数据库密码**。

### 5.2 服务启动

```powershell
docker compose up -d --build
docker compose ps
docker compose logs app --tail 20
```

结果：

| 服务 | 状态 |
|---|---|
| mysql | Up (healthy) — 由 `healthcheck` 每 5s 探测 |
| app | Up，端口 `0.0.0.0:8888->8888/tcp` |

- app 通过 `depends_on: condition: service_healthy` 等待 MySQL 就绪后启动，未出现启动竞态
- app 日志出现 `Starting server at 0.0.0.0:8888...`
- 浏览器访问 `http://localhost:8888/` 正常；注册、登录、待办操作均成功

### 5.3 数据持久化三连测

先通过页面注册用户并创建待办，然后依次执行：

| # | 操作 | 期望 | 实际 |
|---|---|---|---|
| 1 | `docker compose stop` → `docker compose start` | 数据仍在 | ✅ 仍在 |
| 2 | `docker compose down` → `docker compose up -d`（容器被删除重建） | 数据仍在 | ✅ 仍在 |
| 3 | `docker compose down -v` → `docker compose up -d`（连数据卷删除） | 数据消失，表结构重建 | ✅ 数据消失、表存在 |

**结论**：数据持久化由命名卷 `mysql-data` 承担——测试 2 证明"容器重建不丢数据"，测试 3 反证"删除卷则数据丢失"。两者结合才能排除"数据存放在容器临时层"的可能。

## 6. 过程中发现并修复的问题

| 问题 | 现象 | 修复 |
|---|---|---|
| 中间件缺少 `return` | 无效 Token 时 `tk` 为 `nil`，访问 `tk.ExpiresAt` 触发 panic；因 401 已先写出且 go-zero 恢复中间件兜住 panic，手工 curl 无法发现 | 错误分支补 `return`；由单元测试暴露 |
| `sql/init.sql` 语法错误 | 在全新的 MySQL 容器中执行报 1064；本机因表已存在（`IF NOT EXISTS`）从未暴露 | 修正 `todos` 表缺少/多余的逗号；在空库上重新验证 |
| `.dockerignore` 与 `Dockerfile` 冲突 | 构建报 `CopyIgnoredFile: build/app-linux is excluded by .dockerignore` | 从 `.dockerignore` 移除 `build/` |
| 更新接口返回旧数据 | 修改邮箱后响应中仍是旧邮箱（`updated_at` 也是旧时间） | 改为"先写库 → 再查询 → 返回最新数据" |
| 首页 404 | 未把 `web/` 复制进镜像 | `Dockerfile` 中 `COPY web ./web` |
